## P1 - MIGRAÇÃO TOTAL PARA TYPESCRIPT

> Após concluir P0, migrar TODO o projeto para TypeScript (strict).
> Estratégia: incremental por layer, mantendo o app rodando (checkpoint por layer).
> Os testes atuais foram removidos (ver P2) — usamos `npm run lint`/build para regressão
> durante a migração.

### Setup de toolchain
- [x] Criar `tsconfig.json` (strict, `module: NodeNext`, `target: ES2022`, `outDir: dist/`)
- [x] Adicionar devDependencies: `typescript` (~5.9.3), `tsx` (dev runtime), `@types/node`,
      `@types/express`, `@types/jsonwebtoken`, `@types/bcrypt`, `@types/cors`,
      `@types/compression`, `@types/validator`, `@types/swagger-ui-express`, `typescript-eslint`.
- [x] `.ts` no ESLint (migrar `eslint.config.js` para compat TS; `no-unused-vars` TS).

### Migração por camada (checkpoint a cada camada com `npm run build`)
- [x] **shared/** (`utils/*.js` → `.ts`): tipos para DomainError, HttpError, configs.
- [x] **domain/** (`index.js` → `index.ts`): entidade `User`, `AuthService`,
      enums/tipos de resultado, interfaces (ports).
- [x] **infrastructure/**: `database/`, `cache/`, `external-services/`,
      `adapters/`. Tipos dos adapters (implementam ports do domínio).
- [x] **interfaces/**: configs (`env.js`, `appConfig.js`, redis, rate limit, etc.) — tipar o `SecurityConfig` e derivados.
- [x] **application/**: middleware, controllers, routes. Tipos Express (`Request`/`Response`).
- [x] **core/**: `ServiceContainer` tipado (mapa de serviço com tipos), `bootstrap`.
- [x] **app.js** → `app.ts` + entrypoint (extension augmentation `Express.Request.user`).
- [x] Renomear imports `*.js` → `*.ts`/resolver extensions: mantido padrão `.js` no
      source (NodeNext resolve `.ts` automaticamente); `tsc` gera `dist/` com `.js`.

### Entrega da migração
- [x] `npm run build` (tsc → dist/) gerando JS limpo (build OK, lint OK, 0 erros tsc).
- [x] `npm start` / PM2 apontando para dist/ (atualizar `ecosystem.config.cjs`).
- [x] Scripts do package.json atualizados (`dev` com `tsx watch`, `build` com tsc).
- [x] Dockerfile: stage `build` roda `tsc`; imagens de prod consomem `dist/`
      (concluído na fase Docker/P3 abaixo).
